## Why（为什么做）

上游告警程序会发出报警图片与报警 bbox JSON，但一次检测存在误报。需要独立的二次校验服务：对同一批图再跑识别，产出类别与置信度，供上游或其他系统参考以降误报；同时提供人工可查的识别日志台，便于事后核对，但不由人介入改判定结果。

## What（做什么）

建设报警图片二次校验平台（产品命名不绑定具体检测模型）：

1. **入图**：支持 WebAPI 接收图片 + 报警 bbox JSON；支持在指定目录定时发现新图片（及配套 bbox 信息）并入库处理。
2. **二次识别**：对入图执行目标检测式二次识别，产出**类别 + 置信度**（可与原告警 bbox 对照展示，具体算法与模型选型属 DESIGN）。
3. **结果落库**：校验任务与识别结果持久化；v1 **不回写**上游程序。
4. **审核日志台（Web）**：人工查看入图、bbox、二次识别结果与日志；**只读复核，不介入判定、不覆盖模型输出**。

## 视觉调性（前端项目必填，由 0-change 步骤 0.6 预选填入）

- **选定**：3 工业（Industrial）
- **理由**：核心场景是刷图、对照 bbox、看置信度与日志，需要数据密度与监控台气质。
- **参考产品**：Bloomberg Terminal、Grafana、Datadog
- **明确排除**：4 玩具（不严肃）、5 奢华（非品牌向）、7 复古未来（干扰复核效率）

## 范围排除（这次不做）

- 多租户
- 复杂权限体系
- 大盘统计分析

- 向原告警程序主动回调 / 回写告警状态

- 模型在线训练 / 热更新平台化（推理用模型的部署方式留给 DESIGN，但不做训练产品）

## 验收线（粗粒度，不是 AC）

- 上游（或目录投递）能把报警图 + bbox 送进平台，并拿到二次识别的类别与置信度记录。
- 审核人员能在 Web 日志台按任务查看原图、原告警 bbox 与二次识别结果，且无法在台内改写判定结果。
- v1 不依赖对上游的回写即可独立完成「入图 → 识别 → 可查日志」闭环。
